# تحديث الأصناف عبر Excel

واجهة الإدارة: `/admin/product-updates`. الاستيراد القديم `/admin/csv` مستقل ولا يزال متاحًا.

## الاستخدام

1. تنزيل الأصناف الحالية أو قالب فارغ للإضافات. البيانات والقوائم مأخوذة من قاعدة الموقع.
2. تعديل الخلايا البيضاء، ثم رفع ملف `.xlsx` من نفس الواجهة؛ الملفات القديمة وCSV غير مقبولة في v2.
3. مراجعة القيم القديمة والجديدة والأخطاء. **الخانة الاختيارية الفارغة تمسح القيمة الحالية**، والكمية صفر قيمة صحيحة.
4. تأكيد الحفظ. حذف صنف أو مسح قيمة يحتاج تحديد مربع الإقرار في المعاينة. أي خطأ يمنع حفظ الملف كله.

«حذف» في عمود الإجراء يحذف الصنف منطقيًا؛ إزالة الصف من Excel تتركه كما هو. «إضافة» تتطلب صفًا جديدًا بلا معرّفات، وتضيف صنفًا بسيطًا كمسودة. للأصناف متعددة الخيارات تكون الأسعار والكميات في الورقة الثالثة. النشر، إنشاء الخيارات، الأصناف بلا خيارات، كميات السيريال، والتفاصيل المعقدة تُدار من شاشات الموقع. الصور لا تدخل الملف ولا تُعدل.

كل جزء يحتوي حتى 1000 صف بيانات إجماليًا في ورقتي الأصناف والخيارات. منتجات أكثر من 999 خيارًا موزعة على أجزاء، ويمكن حفظ تغييرات خيارات مختلفة مستقلًا. إذا عدّلت بيانات الصنف المشتركة في جزء، نزّل بقية أجزائه مجددًا بعد الحفظ.

## عقد API

المسارات تحت `/api/admin/commerce/excel/v2`:

- `GET /parts`: قائمة `{parts: [{part, rows}]}`.
- `GET /export?part=1`: ملف Excel للجزء المطلوب؛ `GET /template`: ملف إضافة فارغ بالقوائم الحالية.
- `POST /preview`: `{file: base64}`؛ الخادم يقرأ Excel مباشرة، ويفحص الأعمدة والخلايا والهوية والإصدارات والصلاحيات.
- `POST /commit`: `{file: base64, previewToken}`. الرمز مرتبط بمحتوى الملف ومستخدم المعاينة، وصالح 30 دقيقة.
- النتيجة: `{errors, previews, summary, committed, previewToken?, replayed?}`؛ كل خطأ يتضمن ورقة وصفًا وعمودًا، وكل تغيير يتضمن القيمة السابقة والجديدة وعلامة المسح.

الحقول والأعمدة وأنواع النتائج معرفة في الحزمة المشتركة `product-updates.ts`. الحد 5 MB للملف، و7 MB لطلب JSON؛ يتم فحص حجم ZIP بعد فك الضغط قبل القراءة. ورقة النظام تحمل بيانات موقعة بمفتاح الجلسة؛ تغيير مفتاح الجلسة يتطلب إعادة تصدير الملفات.

الحفظ يستخدم معاملة Serializable بمهلة خاصة 120 ثانية، مع قفل سجلات الأصناف والخيارات والوحدات وفحص الإصدارات مجددًا. إيصال دائم بمعرّف الملف الفريد في AuditLog يمنع تكرار العملية، بما فيها عمليات الإضافة المتزامنة. سجل التغييرات يحفظ القيم السابقة والجديدة، وتُسجل حركات المخزون والأسعار. سجلات أسعار الخيارات تحمل معرف الخيار في `reason` دون تغيير سعر الصنف الأب.

لا توجد تغييرات جديدة على مخطط قاعدة البيانات. الصور، النشر، والمواصفات لا تُرسل ضمن بيانات التحديث.

## التحقق

- `npm test`: الاختبارات الوحدوية، بما فيها الملف القديم وتقسيم ملفات التحديث.
- `npm run test:product-updates`: اختبارات قاعدة محلية معزولة، تتطلب خادم MariaDB محليًا على `127.0.0.1:53307` وملف اعتماد `.local/mariadb/root.private`. لا تستخدم DATABASE_URL الإنتاجي. تنشئ قاعدة باسم عشوائي وتحذفها بعد الاختبار.
- `npx playwright test -c admin/playwright.config.ts admin/tests/product-updates.spec.ts`: معاينة عربية للجوال والكمبيوتر، ومنع الحفظ عند الأخطاء أو قبل إقرار المسح.
- `npm run typecheck --workspaces`، وبناء الحزم المشتركة والخادم والإدارة.

اختبارات التكامل تشمل: عدم تغيير ملف صادر كما هو، تكرار أسماء الأصناف والبراندات، المحافظة على الأصفار في SKU، المسح والحذف والإضافة، الصلاحيات، الخيارات، السيريال، تعديل الموقع بعد التصدير والمعاينة، إرسال الحفظ مرتين، والتراجع الكامل عند فشل أثناء الكتابة.

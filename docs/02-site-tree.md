# شجرة الموقع الجديدة — «الجيل العربي الرقمي»

> **المبدأ:** الموقع الحالي صفحة هبوط واحدة بلا بيانات (8 مشاهد وشعار ونموذج نسخ). الموقع الجديد **موقع بيانات**: كتالوج، بطاقات مواصفات، مقارنة، تجهيزات، أدلة، ضمان. الحركة تخدم البيانات ولا تحلّ محلها.
> المرجع للمحتوى: `01-company-profile.md`.

---

## 1. تشخيص الوضع الحالي

| المشكلة | الأثر |
|---|---|
| صفحة واحدة فقط (Landing) | لا يوجد مكان لعرض منتج أو مقارنته أو مشاركته برابط |
| لا يوجد كتالوج ولا مواصفات ولا أسعار | الزائر لا يستطيع الشراء أو حتى التقييم |
| الفئات السبع مجرد بطاقات بصور | لا تقود إلى شيء |
| الضمان شعار بلا شروط | لا ثقة قابلة للقياس |
| الحركة (GSAP/Lenis) ثقيلة والمحتوى خفيف | تجربة جميلة بلا فائدة |
| صفحة واحدة = SEO ضعيف | لا يظهر في البحث عن «لابتوب صنعاء» |
| لا بحث ولا فلترة ولا مقارنة | الزائر يعتمد على واتساب لكل سؤال |

**ما نُبقيه:** الهوية والشعار، الثنائية عربي/إنجليزي مع RTL/LTR، الوضع الفاتح/الداكن، أداة «رتّب احتياجك»، الخطوط المحلية، نظام الحركة (يُنظَّم).

## 3. بيانات كل صفحة (هذا هو المهم)

### 3.1 الرئيسية `/`
| القسم | البيانات المعروضة | الحركة |
|---|---|---|
| Hero | الشعار + 3 أرقام حقيقية من البيانات (عدد المنتجات المتوفرة، فئات، سنوات) + زران | دخول متدرج للعنوان، منتج واحد بحركة خفيفة |
| شريط الثقة | ضمان مكتوب · فحص قبل التسليم · درجات الحالة · دعم واتساب | ظهور تتابعي |
| الباحث السريع | 3 أسئلة (الاستخدام، الميزانية، الحجم) → نتائج حيّة من `products.json` | انتقال سلس للنتائج |
| «وصل حديثًا» | آخر 8 بطاقات منتجات ببيانات كاملة | Stagger عند الدخول |
| التجهيزات | 4 باقات بمكوناتها وسعرها | **مشهد مثبّت Pinned:** تتبدل المكونات مع التمرير |
| الفئات | 7 فئات مع عدد المنتجات في كل فئة | Hover/Tap فقط |
| قسم الأدلة | أحدث 3 أدلة | ظهور عند التمرير |
| الأسئلة الشائعة | 5 أسئلة | Accordion |
| CTA | رتّب احتياجك | بسيط بلا استعراض |

### 3.2 المتجر `/shop/:category`
- **فلاتر جانبية:** الماركة، السعر، المعالج، الرام، التخزين، حجم الشاشة، درجة الحالة، المتوفر فقط.
- **فرز:** الأحدث، السعر، حالة البطارية.
- **بطاقة المنتج:** صورة، الاسم، 4 مواصفات رئيسية، درجة الحالة، الضمان، السعر وتاريخ تحديثه، زر مقارنة، زر «اسأل عن الجهاز».
- الحالة محفوظة في الرابط (`?cpu=i5&ram=16`) لقابلية المشاركة.

### 3.3 صفحة المنتج `/shop/:category/:slug`
1. معرض صور
2. السعر والتوفر والضمان ودرجة الحالة
3. **جدول المواصفات الكامل** (من schema القسم 13 في ملف البروفايل)
4. **تقرير الفحص:** كل بند ✔/✘ مع التاريخ
5. «يعمل جيدًا مع»: ملحقات متوافقة (من `compatibleWith`)
6. «مناسب لـ»: روابط للتجهيزات
7. أجهزة مشابهة
8. زر واتساب برسالة معبأة مسبقًا باسم المنتج ورابطه
9. بيانات منظمة `Product` JSON-LD

### 3.4 التجهيزات `/setups/:slug`
- المشكلة التي يحلها التجهيز
- قائمة المكونات (كل مكون يربط بصفحة منتجه) وسبب اختياره
- **ثلاث مستويات للباقة:** اقتصادي · متوازن · متقدم، بسعر كل منها
- مخطط بصري لتوصيل الأجهزة (SVG)
- زر «اطلب هذه الباقة» → واتساب

### 3.5 حلول الشركات `/business`
- مسار العمل (4 خطوات) بزمن لكل خطوة `[يؤكَّد]`
- باقات مكتب (3 أحجام) بمكوناتها
- عقد الدعم: ماذا يشمل وزمن الاستجابة `[يؤكَّد]`
- نموذج عرض السعر: عدد الموظفين، الاحتياج، الميزانية، المدينة → ملخص واتساب/إيميل

### 3.6 الأدوات `/tools`
- **حاسبة UPS:** يدخل أجهزته → واط → VA موصى + منتجات UPS مناسبة من البيانات.
- **فاحص التوافق:** يختار لابتوب وشاشة/Dock → ينجح/فشل مع السبب (منفذ، واط PD، دقة).
- **مساعد اللابتوب:** 3 أسئلة → 3 ترشيحات مع سبب كل واحد.
- **رتّب احتياجك:** الأداة الحالية بعد تحسينها لتقرأ من البيانات.

### 3.7 الضمان `/warranty`
جداول حقيقية: درجات الحالة، قائمة الفحص، ما يشمله الضمان وما لا يشمله، خطوات المطالبة. هذه الصفحة هي أقوى أداة ثقة في الموقع.

### 3.8 الأدلة `/guides`
مقال بجدول مقارنة وخلاصة في أول فقرتين، وروابط منتجات ذات صلة في آخر المقال.

### 3.9 من نحن / التواصل
- قصة المتجر والفريق وصور حقيقية `[يؤكَّد]`
- العنوان والخريطة وساعات العمل وكل أزرار التواصل
- أرقام حية: عدد الأجهزة المفحوصة، عدد الطلبات `[يؤكَّد — لا تُخترع]`

## 5. خطة الحركة عند التمرير (Scroll Motion Plan)

**القاعدة:** الحركة تشرح، لا تزيّن. إن لم تفد القارئ فاحذفها.

| الموضع | التقنية | الغرض |
|---|---|---|
| Hero | GSAP Timeline (دخول) | انطباع أول سريع (≤ 1.2 ثانية) |
| مشهد التجهيزات | ScrollTrigger `pin` + `scrub` | يُري كيف تكتمل المنظومة مكونًا بعد آخر |
| شريط الثقة والبطاقات | `ScrollTrigger.batch` / `stagger` | ظهور متدرج بلا ثقل |
| الأرقام | Count-up عند الظهور | إبراز الرقم الحقيقي |
| صفحة المنتج | تثبيت جدول المواصفات بجانب الصور (CSS `position: sticky`) | قراءة المواصفات مع الصور |
| الأدلة | شريط تقدم القراءة (CSS scroll-driven) | تجربة قراءة |
| انتقال الصفحات | View Transitions API | استمرارية بصرية |

**قواعد صارمة:**
1. حرّك `transform` و`opacity` فقط.
2. `prefers-reduced-motion`: تعطيل كل الحركة عدا الظهور البسيط.
3. على الجوال: بلا Pin ثقيل، وأقل stagger.
4. محتوى الصفحة يظهر كاملًا إن فشل JavaScript.
5. لا حركة تؤخر وصول الزائر إلى السعر أو زر الواتساب.
6. Lenis متزامن مع ScrollTrigger، ويُعطّل داخل الحقول والقوائم.
7. ميزانية الأداء: LCP ≤ 2.5 ثانية على شبكة 4G متوسطة.

## 6. البنية التقنية المقترحة

| الطبقة | القرار |
|---|---|
| الإطار | يبقى React 19 + Vite + TypeScript + Tailwind |
| التوجيه | React Router (مسارات حقيقية) |
| SEO | Pre-render ثابت (`vite-react-ssg` أو Astro إن أراد إعادة هيكلة) |
| البيانات | ملفات JSON مُتحقَّق منها بـ Zod عند البناء، بلا قاعدة بيانات في المرحلة الأولى |
| البحث | Fuse.js على الجهاز (يدعم العربية بعد تطبيع النص) |
| الصور | WebP/AVIF بأحجام متعددة + lazy |
| الطلب | روابط `wa.me` برسالة مُعبّأة، بلا حسابات |
| الاستضافة | ثابتة (Netlify / Cloudflare Pages / Vercel) |
| تحديث الأسعار | تعديل `products.json` أو لوحة بسيطة لاحقًا (Decap CMS) |

## 7. مراحل التنفيذ

**المرحلة 1 — الأساس والبيانات (أهم مرحلة)**
مخطط البيانات، 20–30 منتجًا حقيقيًا، التوجيه، بطاقة المنتج، المتجر مع الفلاتر.

**المرحلة 2 — الثقة**
صفحة الضمان والفحص ودرجات الحالة، الأسئلة الشائعة، من نحن، التواصل.

**المرحلة 3 — القيمة**
التجهيزات (3 مستويات)، حلول الشركات، المقارنة، الأدوات الأربع.

**المرحلة 4 — النمو**
الأدلة (14)، SEO وبيانات منظمة، تحسين الأداء، تتبع الأحداث (نقرات واتساب، فلاتر، مقارنات).

**المرحلة 5 — الصقل**
الحركة النهائية، اختبار على أجهزة ضعيفة، إمكانية الوصول، مراجعة المحتوى.

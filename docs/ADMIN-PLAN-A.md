# خطة المرحلة A

المستودع الفعلي هو `lenis/`؛ يبقى المتجر في جذره وتضاف مساحات العمل `admin/` و`server/` و`packages/shared/` فيه. الفرع: `feature/admin-system`. كانت هناك تعديلات محلية قبل بدء العمل؛ لا تُحذف ولا تُستبدل.

1. نقل مخططات Zod الحالية دون تغيير إلى الحزمة المشتركة، وإعادة تصديرها من المسار القديم. إضافة مخططات الهوية والصلاحيات المشتركة فقط.
2. بناء جميع نماذج PostgreSQL وترحيل أولي مع العلاقات والفهارس والقيود؛ عدم استيراد منتجات أو عملاء تجريبيين.
3. Fastify 5، Prisma 7 مع PostgreSQL driver adapter، argon2id، جلسات قاعدة بيانات مخزنة كهاش، CSRF، قفل مؤقت، TOTP مشفر، سجل تدقيق داخل المعاملات، وإدارة الموظفين للمالك.
4. React 19 وVite، Tailwind، Radix، TanStack Query/Table، React Hook Form وZod؛ واجهة عربية افتراضيًا مع الإنجليزية، مظهرين، صفحات حساب وأمان وموظفين ولوحة فارغة صادقة.
5. Docker للتطوير، إعدادات موثقة، CLI تفاعلي لإنشاء المالك، اختبارات وحدات وتكامل على PostgreSQL حقيقية والتحقق البصري عند 360 و1280 بكسل.

تُستخدم OTPAuth بدلاً من otplib لصغر واجهتها ودعم RFC 6238؛ لا يتغير معيار TOTP. تُؤجل رسوم Recharts حتى وجود بيانات فعلية في المرحلة D. يستخدم Docker Node 24 LTS (يلبي Node 20+ ومتطلبات Prisma 7). المصادر: [Fastify Zod provider](https://github.com/fastify/fastify-type-provider-zod)، [OTPAuth](https://github.com/hectorm/otpauth)، [Prisma](https://www.prisma.io/docs/orm).

المخاطر: محرك Docker غير متصل عند الفحص الأول؛ إعداد HTTPS والنسخ الاحتياطية واختبارات البيع/الكتالوج تؤجل إلى مراحلها. ملفات بيانات المتجر غير متتبعة سابقًا؛ يسجل ملف إعادة التصدير الجديد فقط دون تعديل JSON أو التصميم.
